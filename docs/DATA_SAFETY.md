# Data Safety — Play Store Declaration Notes

Precise, current-state reference for filling out Play Console's Data Safety form. Every claim
below is written against the actual code paths (revised for Internet mode, plans and the managed
AI service), not aspirational. **Have the final Play Console answers reviewed before release.** If a future
change alters any of this, update this file in the same commit — a stale Data Safety claim is a
Play Store policy violation, not just a documentation error.

## What MeetingMind actually does with data

**Recordings, transcripts and AI-generated content are stored on the device, and by default
(Offline mode) processed there too.** In the default Offline mode nothing is uploaded — see
`docs/AI_ARCHITECTURE.md` for the local inference architecture (VAD, ASR, diarization, and the
local LLM all run on-device via sherpa-onnx and MediaPipe).

**Internet mode is an opt-in the user chooses.** When it is on, audio and text for the work being
done are sent to a cloud AI provider: to Google (Gemini) directly with the user's own API key, or,
on a MeetingMind plan or free allowance, through MeetingMind's managed service
(`server/gemini-proxy`), which forwards to Google and meters usage. AI text can also go to DeepSeek
(through `server/deepseek-proxy`, or with the user's own key) when Gemini is unavailable. A setting
that cannot be read falls back to Offline, so nothing is uploaded by accident. The managed service
does not store audio or transcripts; it keeps only usage counters (below).

Data collected/processed:

| Data | Collected? | Shared off-device? | Where it lives |
|---|---|---|---|
| Audio recordings | Yes (created by the app) | No | `context.filesDir/meetings/<id>/` — app-private storage |
| Transcripts, summaries, decisions, action items, questions | Yes (generated by the app) | No | Room database, app-private storage |
| Model files (ASR/diarization/LLM weights) | Downloaded by the app, on user request | Downloaded *from* Hugging Face / GitHub Releases over HTTPS — never uploaded | App-private storage |
| Audio and text sent for cloud AI | Only in Internet mode, for the request being made | Yes — to Google (Gemini), via MeetingMind's managed service when the user has no key of their own; to DeepSeek for some text | Processed to answer the request; MeetingMind's managed service stores no audio or text, only the usage counters below |
| Purchase and subscription status | Only if the user buys or restores a plan | Yes — to Google Play and RevenueCat (billing) | Entitlement state is cached on the device; payment details never reach MeetingMind |
| Anonymous identifiers: a random install id, and RevenueCat's app user id | Only when a managed cloud request or a purchase is made | Yes — to MeetingMind's managed service (to meter usage and check the plan) and to RevenueCat | The service keeps usage counters per id: seconds of cloud audio and number of AI actions, per month |
| Account info (name, email) | Only if sign-in is available in the build and the user chooses it | Yes — to Firebase Authentication, for sign-in only | Not stored by MeetingMind beyond the session; managed by Firebase. (This build has no sign-in screen.) |
| Lightweight meeting metadata (title, date, duration, participant count, source type — never audio or transcript text) | Would be synced to Firestore if cloud sync were enabled | N/A in this build | `FirestoreSyncManager.syncMeetingMetadata()` exists in code but is **not wired to any UI** in this build — unreachable, dead code. Nothing is actually synced. |

## Sign-in (optional)

The code for Google Sign-In via Firebase Authentication exists, but **this build has no sign-in
screen** and it is not configured; nothing in the app requires an account. Onboarding
and all recording/transcription/AI functionality work fully without signing in. Signing in
transmits standard Google account identifiers (name, email, profile photo URL) to Firebase for
authentication purposes only — never meeting content.

## Network access

The app requests `INTERNET` permission for these purposes:

1. Downloading AI model files and Bible text the user chose to install.
2. Cloud AI, only in Internet mode: Gemini (directly, or via MeetingMind's managed service) and DeepSeek.
3. Plans: Google Play Billing and RevenueCat, to show prices, buy, restore and check what the user owns.
4. Firebase Authentication, only if sign-in is ever offered and the user chooses it.

In Offline mode, recording, transcription, diarization, summarization and Ask are 100% local inference
with no network dependency. **There is no analytics or advertising SDK and no tracking.** If product analytics
are ever added, this file, the in-app privacy text and the Data Safety form must change first, with an opt-out.

## Permissions and why each is needed

| Permission | Why |
|---|---|
| `RECORD_AUDIO` | Core recording functionality |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MICROPHONE` | Keeps recording alive when the app is backgrounded/screen-locked |
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | Global playback service (Media3 `MediaSessionService`) for the mini-player/lock-screen controls |
| `FOREGROUND_SERVICE_DATA_SYNC` | Required on Android 14+ for the WorkManager-backed background AI processing job (`MeetingProcessingWorker`) |
| `POST_NOTIFICATIONS` | Recording/playback/processing status notifications |
| `WAKE_LOCK` | Prevents the CPU from sleeping mid-recording |
| `INTERNET` | Model and Bible downloads, Internet-mode cloud AI, plans and billing (see above) — never used in Offline mode for AI inference |

**No broad storage permission is requested.** Importing audio/video uses the system document
picker (`ActivityResultContracts.GetContent`), which needs no storage permission on any supported
API level.

## Android Auto Backup / device transfer

Recordings (`filesDir/meetings/`) and the Room database (`meetmind_database`, containing
transcripts/summaries/decisions/action items) are explicitly excluded from Android's Auto Backup
and device-transfer via `res/xml/data_extraction_rules.xml` / `res/xml/backup_rules.xml` — they
never leave the device through that mechanism either, consistent with the local-first claim above.

## Accurate claims for the Data Safety form

Use language like: *"Meeting recordings and transcripts are stored on your device. By default they are
processed on the device and never uploaded. If you turn on Internet mode, the audio or text for the work
being done is sent to a cloud AI provider (Google Gemini, or DeepSeek for some text), directly with your own
key or through MeetingMind's service. If you buy a plan, purchase status is handled by Google Play and
RevenueCat, and anonymous identifiers are used to apply your plan's allowance."*

Do **not** claim "no data is ever transmitted" or "audio is never uploaded": Internet mode uploads it, by
the user's choice. Do not claim "no identifiers are collected" either: the managed service and RevenueCat
use anonymous ones.

## Known follow-up

`FirestoreSyncManager` is currently dead code (correctly scoped to metadata-only, but unreachable
from any UI). Either wire it up behind an explicit, clearly-labeled opt-in toggle in Settings, or
remove it, before shipping a build where the Data Safety form claims anything about cloud sync.
Until then, this file's "not wired to any UI" note must stay accurate.
