## Built

1. **`inbox_items`** in schema 21 (`core/database/Inbox.kt`, `MIGRATION_20_21`). Columns: kind, uri, text, title, status, `proposedJson`, `createdAt`, `processedAt`, `resultRefJson`, with an index on status.
2. **Share in.** `ACTION_SEND` and `ACTION_SEND_MULTIPLE` filters on `MainActivity` for `text/*`, `application/pdf`, `audio/*`, `image/*`. `ShareIntentParser` turns an intent into parts. `ShareIn` copies files into `filesDir/inbox`, adds them to the Inbox and opens it (`DeepLink.Inbox`).
3. **Propose, never file.** `InboxProposer` picks a target by name: a project, then an organisation, then a person mentioned in the title or text. It proposes an action: a note, tasks, a decision or a contact. An optional model refines the proposal, but tasks, decisions and contact fields must be grounded in the shared text (at least 60% word overlap for tasks and decisions, a substring for contact fields). An unknown target is ignored. A proposal that needs what the text lacks falls back to a note. `InboxFiler` files only when the person confirms, never twice.
4. **Inbox screen** (`Routes.WORK_INBOX`). Each item has a proposal card: Confirm, Change…, File to…, Dismiss. Audio offers "Transcribe it", which hands off to the existing import flow (`Routes.IMPORT_FILE`). A "Scan" button uses the ML Kit document scanner.
5. **Where it shows:** an "Inbox · N to file" line on the Pulse, and an Inbox card in the Work space.
6. **Privacy.** The model is chosen through `WorkModels.forPack`: anything sensitive (on-device setting, sensitive profile, or a confidential match) only meets the local model. The prompt starts with the fidelity contract.
7. **Deep links.** `DeepLink` gains `Inbox`, `WorkSpace`, `Prepare`, `RecordEvent` and `WeeklyReview`, plus `DeepLinks.open()`. The last three are wired in W12.

## Not built or changed

- **PDF text is not extracted.** There is no PDF text library in the app, and a new third-party SDK needs the orchestrator's say-so. PDFs get title-only proposals (a note holding the file). Adding a text extractor later only feeds the same proposer.
- **Shared URLs are not fetched.** A fetch would send something over the network the person didn't ask for. A link is kept as an item with its host as the title.
- **New dependency: ML Kit Document Scanner** (`com.google.android.gms:play-services-mlkit-document-scanner:16.0.0`). It runs on the device. It is listed in `THIRD_PARTY_NOTICES.md`. It is the one new dependency in W11. Please confirm it's acceptable.
- **No Compose UI test for the Inbox screen.** The behaviour behind it (parse, propose, file, dismiss) is tested; the screen itself has not been exercised by a UI test, nor on a device.
- Images are kept as items and filed as notes with the file attached. No OCR.

## How to see it

Share text, a link, a PDF, a photo or an audio file to MeetingMind from another app. It opens the Inbox with a proposal. Or Work space → Inbox → Scan.

## Risks / questions for the orchestrator

- The scanner needs Google Play services on the device; without it the Scan button does nothing useful. Sharing still works.
- Title-only PDF proposals are thin. A PDF text library would fix that; it needs approval.
